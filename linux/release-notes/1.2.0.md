Phone controls: what ts5-tui sets, from your phone.

- Controls, on the chat page (owner's key only, this machine and your tailnet only). Models: load, unload, delete, download, the context length. The machine: temperatures, the fan's mode, GPU and memory. Settings: every row of ts5-tui's, tool switches included. When ts5-tui asks something (delete this model?), the question comes to the phone. It works the running ts5-tui itself, so both show the same thing; if none is running, the server starts one in its tmux session. With the background service, the service reaches the owner's ts5-tui through /run/tokenstation (the package sets that up).
- Per user: the models they may use (Access, a user's Models row; any model by default), whether they may switch the loaded model (the chat page's model name becomes a menu), and a last day after which none of their keys gets in. A chat with a model that isn't theirs is refused with the list of theirs. A switched-off key, a paused user's or one past their last day is refused with a line in the log saying which and whose (once a minute per key).
- Users from the phone: Controls has a Users tab with each user's page as ts5-tui has it (preset, web search, tools, models, switching, reading their chats, tokens a day, longest reply, last day, paused), add and remove users, keys on, off or removed, and a new key's QR codes shown on the phone once, never on the TV's screen. Share by Tailscale stays on ts5-tui's Access page for now.
- One chat list: the owner's chats on the chat page are ts5-tui's own chats, both ways. A chat begun on the phone opens in ts5-tui (Ctrl+O, /open), one begun in ts5-tui opens on the phone, and a chat open in ts5-tui picks up what the phone adds to it within a second. The chat page fetches the list again when it comes back into view and every 15 s. A tool's results and summaries stay in ts5-tui's file and aren't shown on the phone. Chats the chat page kept for the owner before move into ts5-tui's list the next time each is written. Users' chats stay theirs. With the background service the owner's chat page chats stay apart for now.
- /feedback from the phone: Controls' Settings tab has a Feedback box. Write what went wrong, choose whether the log's last lines and the chat open in ts5-tui go in, and ts5-tui makes the report the same way /feedback does (keys, addresses, names and paths taken out on the machine). The whole report is shown on the phone first; then Send it, Save on the machine, or Cancel. Only the report shown can be sent, and the phone says when it was sent and its report id. The server's log notes that a report was sent, never its words. Reports now also take out the HOME folder when it isn't the login's own (a test's, or one set for sudo).
