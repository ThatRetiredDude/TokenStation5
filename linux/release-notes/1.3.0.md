The model in ts5-tui can install and use terminal programs and stay with a long task: its sandbox has a Linux system of its own, a message gets as many tool steps as its work takes, and a task that outgrows the chat goes on from the model's notes and your request. Without a key the web search is a regular web search, Chromium is the model's browser, and Google can be what it searches. All of it comes from one long terminal session with a 9B model on a PS5: it tried to install programs, went in circles, and was cut off after twelve rounds of tools.

**The sandbox gets a Linux system of its own**

- The model's commands run in a Debian 13 of their own, inside the same sandbox as before, and the model is root there. `apt-get install`, `pip install` and `npm install -g` work, `sudo` just runs the command, and what gets installed stays for later commands and chats. In the session behind this release a model tried `sudo apt-get install -y btop` twenty times and was refused each time; that command now installs btop.
- None of it touches your system. Root in there is root over that system's files only: on your machine each of its processes is you, with no more rights than you have. A command still sees none of your home folder and none of your environment variables, can change only the folder ts5-tui was started in, and what it starts ends with it. It is the same bubblewrap sandbox, not a virtual machine: no memory of its own, and a command starts in milliseconds.
- The first command sets the system up: a 30 MB download of Debian's slim image files (as Debian's image builders publish them, at one fixed commit, checked by SHA-256), unpacked to `~/.local/share/tokenstation/sandbox/box` (about 90 MiB), then its basic tools: python3, pip, git, curl and wget. The line under the chat says so while it happens. When it can't be set up (no network), the command runs in the sandbox as it was, and the model is told.
- A command in it may take 10 minutes (2 before), so an install has time to finish.
- Settings → Sandbox system, or `/sandbox box off`, goes back to your machine's own system, read-only. `/sandbox reset box` removes the sandbox's system, and the next command sets up a fresh one. `/sandbox folder DIR` moves it with the toolbox to another drive. `ts5-tui --run-command 'CMD' --sandbox box` (or `plain`) runs one command either way.
- For x86-64 machines. No service manager runs in it, so `systemctl` starts nothing: the model is told to start a server in the command that uses it.

**A long task goes on**

- A message that takes many tool calls no longer ends with "This chat is full". Once its calls take the chat past the task window (24,000 tokens), the long outputs of its earlier commands and file reads give way: the model keeps how each ended and its first and last lines, every call and every short result stay word for word, and the newest results stay whole. The chat marks each "left out later, for room"; you still see them in full.
- When that no longer makes an eighth of the window free (a task of long web pages, or of long files written), or the chat no longer fits the model's memory, the model writes notes on its work (its steps and which are done, the very next step, the facts it found, what failed and why, its decisions) and goes on from them.
- Why outputs first: on a PS5 a 9B model read sixteen files and wrote a line on each through a window of 8,000 tokens in 4 min 33 s, 2 min of it spent on six sets of notes (16 to 24 s each; 47 s for one set through 24,000). Both times the notes added the sixteen line counts up themselves, wrongly, and the model wrote that sum into its file.
- With outputs giving way first, the same task through the default window of 24,000 tokens took 2 min 10 s with no notes at all and every value right, and through 8,000 tokens 2 min 30 s with two sets of notes. Outputs giving way cost 4 to 6 s each time (one reading of the shorter chat); a set of notes cost about 21 s.
- Your request stays word for word: it goes to the model beside the notes, with anything you typed while it worked, whatever the notes made of it. The model's latest step, which it has not read yet, stays as it was too (up to three eighths of the window: at a quarter of 8,000 tokens a file's first 150 lines did not stay, and the model read the file again).
- Under the notes the model gets ts5-tui's own list of the calls it made in the task, each with how it ended (a failed one with the last line it gave back, one that gave back a single line with that line), and is told that the list is right where the two differ. Notes are a model's memory of the work, not a record of it: on a PS5 a 9B model's notes named a finished step as the next one and gave the wrong cause for a failed copy, and after them it wrote a file a second time and made the failed copy again.
- Notes written a second time bring the first ones up to date instead of carrying them over, and the next step comes near the top, so notes that run out of room still say where to go on. They may be 1,024 tokens long at least (a sixth of the task window when that is more).
- The notes are asked to hold the values themselves (the lines a command printed, a size, a version), above all what you asked to be told at the end, and beside your request the model is told to report only what it can see in its notes, the list of calls or a tool's result, and to read anything else again first. In a run on a PS5 a 9B model's notes said only that its scripts "print the memory" and "print the Python version", and its answer then gave a memory size and a Python version that no command had printed.
- Notes that say what the notes before them said are written a second time, anew. On a PS5 a 9B model built a small program with tests through a window of 8,000 tokens; six of its tests failed, and its notes then came out the same fifteen times in fifteen minutes, word for word, with a step as next that it had long done. After each set it went back to the same failing tests and never reached the three steps after them. In another run the third set of notes differed from the second in one line of thirty and left out three files counted since. Such notes (no new line, or one in twenty at most) are now asked for once more, not from the earlier notes, which the model would copy again, but from ts5-tui's own list of the task's calls with how each ended, the earlier notes' facts, and the work since.
- A task that goes in circles ends by itself. Beside notes that came out word for word as the ones before, the model is told that this stretch of work brought the task no further: to take the step a different way, or to leave it, go on with the steps that do not depend on it, and say at the end what could not be done. After three such sets in a row it is told to stop and say what is done, what is not and what is in the way, and the chat says why. "go on" starts it again.
- Notes are asked to work nothing out (no sum, no count, no "largest so far") and to copy numbers as they stand: what has to be worked out is a step for a command. The terminal tool's words say the same to the model: a command does the counting, adding and comparing.
- The model is told that every command starts in the same folder again: a `cd` in one call does not last to the next.
- An answer given straight from the notes, with no call between them and it, is asked about once before it stands: ts5-tui tells the model to read again each value that is not there to see and to answer once more, and the chat shows a line where it did. It asks only when the notes replaced calls of that same message.
- "Notes on the task" marks the place in the chat; a click opens them. Everything above stays on the screen and in the saved file.
- Settings → Task window (8,000 to 64,000 tokens, or the whole context), or `/tools window N` and `/tools window off`. A window keeps a long task quick and a small model on track; without one, notes are written only when the chat is full.
- A detail the notes left out is not lost: from the first notes or summary of a chat on, the model has a tool that looks up words in the part they replaced (`search_earlier`: a command it ran and what came back, a path, the words of an error) and gets the lines that have them.
- A command made again after notes is no longer called a repeat: what it gave back before is not the model's to read any more.

- Qwen3.5: the message after one with many tool calls no longer reads the whole chat again. Its engine state only goes forward, so ts5 keeps copies of it to go back to, and all of them sat at the latest turns, while the next message's prompt differs from where the reply to the message before started (that reply's thinking is sent only until the user writes again). One copy now stays there. On a PS5 such a message read all 4,902 tokens of the chat again, about 7 seconds; the longer the chat, the longer that took.

**Google as a search source**

- Settings → Search source has a new choice, Google (`/tools search google`; `TS5_SEARCH_SOURCE=google` for the service; `"web_search_source": "google"` in a request). ts5 reads Google's results page through the Chromium on the machine and gives the model the answer Google's AI writes at the top when it shows one, the results with their passages, and where each leads. The model is told to check that answer against the results.
- Google's page names its results by addresses of its own that send on, and Google says where two of them lead per search (more get a page that says to wait, which ts5 does not sit out or go around). So ts5 asks Google for the first two (the way a click asks, without going there: a result's site hears nothing until the model opens it) and takes the other results' addresses from the same search on DuckDuckGo, made while the browser reads Google's page and listed under it.
- On a PS5 a Google search took 4.6 to 6.6 seconds, with Chromium using about 500 MiB of memory while it ran.
- It is offered where a Chromium is installed. A browser starts for each search, so a search takes seconds, and it is not started with less than 900 MiB of memory free.
- Google's question about cookies is answered with its button for no. Its check for robots is not answered: the search then goes to DuckDuckGo (then Grokipedia, then Wikipedia), and the model is told why.
- The web through DuckDuckGo stays the default.

**The steps a message gets**

- A model that keeps calling tools was stopped after twelve rounds of them, whatever it was doing, and the chat said "the model used all the rounds of tools one message gets". It now gets 50 steps for one message (Settings → Tool steps: 12, 25, 50, 100 or no limit; `/tools steps N`), and then ts5-tui asks instead of stopping: **Go on** (as many steps again), **Don't ask again for this message**, or **No, answer now**.
- What the limit was really catching is caught by itself now: a call the model made before in the same message, with the same result back, is marked "the same as before" and the model is told that making it again changes nothing. After three such calls in a row it has to answer and say what is in the way. In the session behind this release one command was run 26 times with the same answer.
- The turn in which the model has to answer was sent without its tools, so the chat's prompt changed at its start and the engine read the whole chat again: 12 to 24 s each time on a PS5 at 9,000 to 16,500 tokens, ten times in that session, and once more on the next turn. Such a turn now has the same prompt as every other turn and is read on from where the chat stands.
- For the same reason the web search stays offered in a chat that needed it once (ts5-tui's `"web_search": "auto"`), instead of coming and going with each message's wording.

**With the sandbox's Linux system switched off**

- With Sandbox system off, commands run on your machine's own system, read-only, as before this release. When a command failed there because of that (`apt`, `sudo`), the hint told the model to "install tools in ~ instead, such as pip install NAME". The model then ran `pip install npm`, `pip install git` and `pip install curl`, which install Python packages of those names, and reported the programs as installed. The hint and the terminal tool's description now say that system installs can't work there and are not to be tried again, that pip has Python packages only, and to tell you the command to run yourself when a program is missing.

**Web search without a key is a web search**

- Without a web search key the search was Wikipedia. It is now a regular web search: DuckDuckGo's results (title, address and a line or two of each, eight of them, no advertisements), and the model opens the pages it needs. No key and no account. When DuckDuckGo can't be searched, the search goes to Grokipedia, and when that can't be searched either, to Wikipedia; the model is told which it got.
- Settings → Search source (or `/tools search web`, `grokipedia`, `wikipedia`, `both`) picks, and `TS5_SEARCH_SOURCE` in `/etc/default/tokenstation` for the service. A setup with `TS5_ENCYCLOPEDIA` keeps its encyclopedia. ts5-tui settings saved by an earlier version, where Wikipedia was the default, move to the web once.
- With a Tavily key nothing changes.

**Chromium is the model's browser**

- Most sites show nothing without their scripts, so the browser tool is on by default now, and Chromium comes with the package: the .deb and the .rpm recommend it (`apt` and `dnf` install it beside TokenStation5; on Arch it is an optional dependency). ts5-tui settings saved by an earlier version get the browser tool switched on once; `/tools browser off` switches it off.
- `/browser install` and `ts5-tui --install-browser chromium` install the full Chromium where the system has it. On Debian 13 they took the smaller `chromium-headless-shell`, which is used only where there is no other now.
- Pages are asked for as before, as Chrome on a MacBook asks for them. Without a browser installed, pages are read in the text view, as before.
- Chromium takes memory beside the model while a page is open: on a PS5 beside a 14B model, 155 MiB waiting and up to 494 MiB on the heaviest page (measured with the headless shell).
