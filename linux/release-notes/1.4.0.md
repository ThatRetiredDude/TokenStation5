**ts5-tui**

- **The sandbox stays up between commands.** A server, a database or a build the model starts in the background (`prog > /tmp/prog.log 2>&1 &`) is still there for its next command, and `/tmp` keeps what earlier commands wrote. The model is told so in the terminal tool's description and under a command that left something running. The sandbox ends with the chat (a new or opened chat), when ts5-tui quits (also when it is killed: the shell inside ends as soon as ts5-tui's end of its pipe closes, and every program in the sandbox with it), when the sandbox is reset or moved, when the network switch or the sandbox system changes, or after 30 minutes unused. A command past its time limit is still stopped, with what it started, and the sandbox goes on. `TS5_SANDBOX_KEEP=0` gives every command a sandbox of its own, as before. `ts5-tui --run-command` given more than once runs the commands one after the other in one sandbox.
- **Settings → Sandbox memory:** a cap on the memory all the sandbox's programs hold together, 2 GiB by default (512 MiB, 1, 2, 4, 8 GiB or no cap; `sandbox_memory` in MiB in tui.conf), so a runaway command can't take the model's memory. Where your systemd can give the sandbox a memory limit of its own, the kernel keeps to it (it ends the biggest program and the sandbox goes on); else ts5-tui adds up what the sandbox's programs hold four times a second and ends the biggest past the cap. The model is told which program was ended, how much it held and what the cap is, and to use less at once. The row shows what the sandbox holds now. Each start and each program ended goes as a line into `~/.local/share/tokenstation/sandbox/sandbox.log`.
- **Unattended tasks.** `/task GOAL` (or `ts5-tui --task 'GOAL'` from a shell) hands the model a job it works on by itself, for hours, in the sandbox, with nobody asked anything. It runs in a program of its own, so it keeps going when ts5-tui closes (the model it uses stays loaded until the task ends, then it is unloaded unless Settings → When you quit keeps it), and when the model's server starts again (it waits up to 10 minutes and goes on where it was). Its commands run in the sandbox without asking; anything that would reach outside it (a button or typing on a web page, a change on GitHub, outside tools, the file tools) is refused with a plain word to the model, and counted. It ends when the model answers (**done**), when its work goes in circles or keeps repeating (**stuck**), at its limits (**steps**, 200; **hours**, 4; **tokens** the model writes, none: `task_steps`, `task_hours`, `task_tokens` in tui.conf, or `--steps`, `--hours`, `--tokens`), when stopped (`/task stop`, `ts5-tui --task-stop ID`), or when it fails. One task at a time. `/task` (or `ts5-tui --tasks`) lists them with how far each got.
- **What a task is told, and how it ends well.** With its goal the model gets its budget (steps, hours, tokens) and is told to do the important parts first and save results to files as it goes; to decide for itself where something is open, and say what it chose; and to check what it made with a command before it calls it done. Its first answer is not taken at its word: once, the program asks it to go through the request part by part and show each with a command, fix what is missing, and report again (`TS5_TASK_CHECK=0` leaves that out). A task cut off by its hours or tokens, or stuck, gets one last turn without tools to write its report from what its commands showed, so every task ends with one.
- **Files for a task.** `ts5-tui --task 'GOAL' --file PATH` (as often as needed) gives the task a copy of each file in `task-files/<id>/` where its commands start, and the model is told their names and to leave them as they are. On the phone, Add files does the same.
- Every task keeps a full log for good in `~/.local/share/tokenstation/tasks/<id>/`: `task.json` (the goal, limits, where it stands, how it ended, its last answer), `log.jsonl` (every model turn with its thinking, every call and what came back, every set of notes, every refusal, with the time), `commands/N.txt` (each command's whole output, not just what the model was shown) and `runner.log`. Its chat is in the chat list too.
- **Watching a task in ts5-tui:** while one runs, the bar shows ⚙ task with its step and time. `/task` lists the tasks with how far each got and the running one's latest steps; `/task open` opens its chat, which follows the task as it goes (its calls and their results too) and takes no messages of yours (`/new` for a chat of your own); `/task stop` ends it. When it ends, ts5-tui says how. Closing the terminal ts5-tui runs in no longer unloads a model a task is using.

**Phone**

- **Controls → Tasks:** the running task with its step, its time and its latest steps, a Stop (tap twice), a box to start a new one, with **Add files** for what it should work on (64 MB a file, 256 MB together; the limits from ts5-tui's settings), and the tasks before it with how each ended. Through `/ts5/control` (the owner's key): `tasks`, `task_start` (`goal`, and `steps`, `hours`, `tokens` if not the usual), `task_stop` (`id`), `task_file` (`name`, `data` in base64, `more` for a further piece), `task_file_drop` (`name`).
- **A notification when a task ends**, however it ended, with its goal and its last answer, on every phone and browser that takes them, whether ts5-tui is in view or not. Tapping it opens Controls → Tasks.
