Fixes only: all 28 findings from a review of 1.2.0. No new features.

**Phone controls**

- Controls, Load: loading a model from the phone also started the download of that model's helper, unasked (1.9 GiB in our test), and the page showed the helper's message in place of the load's. Load only loads now; Get helper is still the helper's own button.
- A model switch that ts5-tui doesn't start (a tuning is running, another model is still loading, the server isn't ts5-tui's own) is refused at once with ts5-tui's reason. Before, the chat page's model menu said "Loading…" for five minutes for a model that never came.
- With the background service and no ts5-tui running, Controls still has this device's own settings (notifications, the chat page's, forget the key) under Settings. Before, the whole page was one line saying ts5-tui isn't running.
- A user who may switch the model no longer cuts off an answer that is being written. Their switch waits for the answer to end (up to a minute) and then loads; if the answer is still going, the switch is refused with that reason. The owner's switch is at once, as before.
- A Yes or a pick tapped on the phone answers the question the phone showed, and no other. If ts5-tui asks something else by then (the first was answered on the TV and a new one came up), the tap is refused and the phone shows the new question.

**Chat page**

- A chat longer than the model's context goes on. The page leaves the oldest messages out of what the model is sent (they stay on screen and in the chat), asks again, and says under the answer how many the model no longer sees. Before, every further message in such a chat was refused with "maximum context length".
- The page looks at the chat list every 15 s and when it comes back into view. It fetched every chat with all its messages each time: 2.8 MB with 60 chats of 20 exchanges. It now asks which chats changed (3 KB for those 60) and fetches only those.
- One chat list: when ts5-tui had gone on with a chat that the phone still showed in its older state, a message sent from the phone was written into the chat twice. It is written once now, after ts5-tui's turns.
- Answers show as they were written: numbered steps with a code block between them keep their numbers (they all showed as "1."), lists inside lists, tables as tables, a code block inside a list as a code block.
- With "Show its thinking" on, the Thinking box stays open while the answer comes, and text selected in an answer stays selected.
- A message sent in the moment the chat list was being read shows its answer as it comes, not up to 15 s after it ended.
- A ts5-tui turn that only used tools shows with the answer that followed it ("used web_search" under that answer), not as an empty bubble. When such a chat goes on from the phone, no empty messages go to the model.
- The chat list's footer says where the chats are kept. For the owner: the same chats as in ts5-tui.
- The chat page's limits (1,000 chats, 256 MB) no longer count ts5-tui's own chats. With the one chat list, an owner with more than that in ts5-tui couldn't save a new chat from the phone.

**Home screen**

- Opened while the server is down or starting (a model loading, the machine just switched on), the app asks again every 3 s, and when it comes back into view, until the server answers. Before, it said "TokenStation5 doesn't answer" until the app was closed by force.
- The model's name is read again every 15 s, so a model switched in ts5-tui or from another device shows.

**Notifications**

- A message sent from the phone while another answer was still coming waits its turn. If the phone was locked before its turn came, the answer was lost. Now it is written, kept in the chat and told by a notification, like an answer that had already started. A request refused before its answer starts no longer leaves its chat marked as still answering.
- "Forget the key" also turns that device's notifications off. Before, a signed-out phone kept getting that user's chat titles and the start of each answer.
- With both Home Screen apps (chat and terminal) and notifications on in each, an answer is told once: a chat's answer by the chat app, ts5-tui's by the terminal app. With one app, both come to it.
- ts5-tui's answers are told by whether the browser terminal is in view, and that is kept when the server starts again (every model load is a start). Before, none came until the browser terminal had been opened once since the last start.
- When the machine's notifications key was made again, a device with notifications on subscribes again by itself the next time its page opens. Before, it said "On" and nothing came.
- Only ts5-tui (or a request with a key) can ask for a notification about a ts5-tui answer. Before, any program on the machine could send one, with any title and text, to the owner's devices.

**ts5-tui**

- It reads the open chat's file right before every save, so turns the phone added in the last second aren't written over.
- While Controls is open on a phone, ts5-tui redraws its screen only after a tap that did something, not for every look (each 1 to 2 s).

**Server**

- A write to a device that takes nothing is given up after 10 s. A phone that dropped off the network in the middle of an answer could hold the engine, and everyone waiting behind it, for about 15 minutes.
- A connection that sends nothing, or stops in the middle of a request, is closed after 30 s, and a whole request has 5 minutes. A body over 64 KB is read only once its key is let in. At most 256 connections are open at once; one more is told to try again.
- /feedback: a secret written in short groups (ab12-cd34-ef56-…) is taken out of a report like any other.
