Six fixes from a review of 1.2.0. Each was reproduced on the released 1.2.0 build first.

- Controls, Load: loading a model from the phone also started the download of that model's helper, unasked (1.9 GiB in our test), and the page showed the helper's message in place of the load's. Load only loads now; Get helper is still the helper's own button.
- A model switch that ts5-tui doesn't start (a tuning is running, another model is still loading, the server isn't ts5-tui's own) is refused at once with ts5-tui's reason. Before, the chat page's model menu said "Loading…" for five minutes for a model that never came.
- A chat longer than the model's context goes on, on the chat page. The page leaves the oldest messages out of what the model is sent (they stay on screen and in the chat), asks again, and says under the answer how many the model no longer sees. Before, every further message in such a chat was refused with "maximum context length".
- The chat page looks at the chat list every 15 s and when it comes back into view. It fetched every chat with all its messages each time: 2.8 MB with 60 chats of 20 exchanges. It now asks which chats changed (3 KB for those 60) and fetches only those.
- A message sent from the phone while another answer was still coming waits its turn. If the phone was locked before its turn came, the answer was lost. Now it is written, kept in the chat and told by a notification, like an answer that had already started. A request refused before its answer starts no longer leaves its chat marked as still answering.
- One chat list: when ts5-tui had gone on with a chat that the phone still showed in its older state, a message sent from the phone was written into the chat twice. It is written once now, after ts5-tui's turns.
