A fix for apps that read the server's answers strictly.

- A model can write bytes that are no character at all (small and untrained models do, and a character can also come split over two tokens). The server sent such bytes on as they came, so an app with a strict reader stopped mid-answer; in our tests a random test model broke 23 of 60 streamed answers. They now arrive as the replacement character �, the same way a browser shows them, and a character split over tokens still arrives whole.
