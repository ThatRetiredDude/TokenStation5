A fix for apps that read the server's answers strictly.

- A model's tokens are bytes, and a model can pick bytes that are no character at all (small and untrained models do; a large one rarely, at a rare character). The server sent such bytes on as they came, so an app with a strict reader stopped mid-answer; in our tests a random test model broke 23 of 60 streamed answers. Now such a pick is taken again: the model's next choice among the tokens that make a real character. It costs one look at the picked token's bytes per token, and the text with the helper on is still the same as with it off.
- An answer that hits its token limit in the middle of a character gets up to 3 more tokens to finish it. If the conversation is full, the half character is left out.
- As a last guard, any bytes that still can't be a character arrive as the replacement character �, the way a browser shows them.
