# Roadmap

Goal: a PS5 on the home network serving local models over an
OpenAI-compatible API, fast enough to use from chat clients and coding tools.

The engine is ts5, our own C++/Vulkan engine ([engine/](../engine/)), running
on the console's GPU as the PS5 title TokenStation5 (PPSA99555,
[ps5/](../ps5/)). [PS5LM Plus](https://github.com/abhi245y/PS5LM), a llama.cpp
port, is the baseline to beat. [FEASIBILITY.md](FEASIBILITY.md) is where this
started.

This is the project's punch list: what's done, what's open and what's next.
Every PR updates it.

Last updated: 2026-10-26.

Testing is on the PS5 (Jared, 2026-10-15): every build is checked and timed on the console with the real models before it is called ready. GitHub only builds the title ([#39](https://github.com/ThatRetiredDude/TokenStation5/pull/39)); the CPU-only test suite it used to run on every push is gone. The testing audit's deeper round ran on the console (2026-10-15 11:17-12:11): the GPU check with 512 reference tokens (the PS5's CPU computes and saves the answers the first time, 7-16 minutes a model) and with 10 tokens (the verify kernels). At 512 tokens Coder 7B (0.20% of the largest logit), Qwen 3 8B (0.21%) and Llama 3.1 8B (0.33%) pass; Llama 3.2 3B fails at 0.78% against the 0.5% bar, at token 62 in the prompt pass; at 10 tokens all four pass within 0.03%. The second round (16:30-16:39, after Jared freed the console) found the cause: the prompt matmuls' packed-f16 sums. Turning them off alone brings the 3B to 0.04% with every top token matching, and Llama 3.1 8B and Coder drop 10 to 40 times too; turning off any other prompt kernel changes nothing. Attention over several tiles, short prompts and the verify sizes all pass. Full f32 costs 8% of prompt speed on the 3B and 13% on Coder, with generation unchanged.

First release (2026-10-24): TokenStation5 01.000.001, packaged for the Prospero Store ([#51](https://github.com/ThatRetiredDude/TokenStation5/pull/51), [#52](https://github.com/ThatRetiredDude/TokenStation5/pull/52)). The release stays pinned to its tag; work merged into main afterwards goes in the next one.

Coding apps (2026-10-24, on the console): Kilo Code made and ran a FizzBuzz script through ts5 with Qwen 2.5 Coder 7B (58 s) and Qwen 3 8B (70 s); Llama 3.1 8B answered in text instead of calling the tools. Kilo's system prompt and tools come to about 15,700 tokens, so it needs the title's `-c auto` (32,768 tokens on the 7B and 8B models, 44,032 on Llama 3.1 8B); the old 8,192 couldn't fit it. The first request reads at 300-350 tok/s (about 50 s); later turns reuse the cached prompt and read only the new 100-160 tokens.

Model check (2026-10-26, on the console, `scripts/model-check.py`, 20 checks of the API the way apps use it, [#89](https://github.com/ThatRetiredDude/TokenStation5/pull/89)): Qwen 3 8B 20/20, Qwen 2.5 Coder 7B 19/20, Llama 3.1 8B 18/20, Llama 3.2 3B 18/20 (before #89: 16/19, 18/19, 18/19, 15/19). ## Next

- [ ] Known-good settings for the download list (Jared, 2026-10-26: "sounds like a win"). Each release carries a settings file for the models in `models.tsv`, built from `scripts/model-check.py` runs on the PS5, so a fresh download starts with settings that work: what it's good for (chat, tools, coding apps), thinking on or off, the context that leaves memory free, and the check's scores for the Models page (and maybe `/v1/models`, so apps can see which models handle tools). Checked so far: Qwen 3 8B, Qwen 2.5 Coder 7B, Llama 3.1 8B, Llama 3.2 3B (#89). Still to run: Qwen 3.5 4B and 9B, Gemma 4 E4B, Gemma 3 12B, Mistral Nemo 12B, Qwen 2.5 0.5B; Gemma and Mistral may need their own tool-call handling first. Entries are keyed by the file's SHA-256 (Hugging Face lists it; the PS5 hashes an FTP copy once) and its Hugging Face repo and file name; a model loads the exact file's settings, else those of the same repo and quant, else its family's (chat template), else the standard ones. A weekly job on the PS5 through the Mac would tune popular models that have no entry yet and open a PR with them (where the popular list comes from is Jared's call: Hugging Face's public counts, or opt-in reports from consoles; without those, nothing leaves the console). The PS5 never holds a GitHub key, since anyone on its network can read the app folder over FTP. The safe first step is a "Not tuned yet" line on the Models page with a QR code that opens a GitHub issue already filled in (Hugging Face repo, file, SHA-256, size, app version, scores if a check ran), which the person submits with their own account. Opt-in reports, if they come later, go through a small service that holds an issues-only key for this repo, accepts only repo, file, SHA-256 and version, checks the file exists on Hugging Face, keeps one issue per model with a counter, limits reports per address and stores no addresses; the setting is off by default and shows what it sends. Neither sends prompts, chats, keys, Tailscale details or anything that identifies the console. Later, a Check or Tune button on the Models page for models outside the list, which would run the same checks on the PS5 and keep the best of the settings the server has. Open there: offered after each download or only on a press, a quick or a thorough pass, settings applied with an Undo or with a "Use these" press, and whether apps see the result.

| Risk | Plan |
